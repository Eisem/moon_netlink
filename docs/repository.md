# 提交文件与本地文件 / Committed files and local files

仓库保存重现源码、公共 API、测试和示例所需的文件。构建结果、下载的依赖和本地资料
保留在工作区，由 `.gitignore` 排除；不需要为了提交而删除它们。

The repository keeps the files needed to reproduce the source, public API, tests and examples. Build outputs, downloaded dependencies and local reference material stay in the workspace and are excluded by `.gitignore`; they do not need to be deleted before committing.

`.ci/` 中的脚本目前需要手动运行；它们不是已配置的 GitHub Actions 工作流。
当前已支持 Snapshot/DesiredState/Diff/Plan、保护 API、dry-run 和确认后的 Apply CLI。
后续集成验收与发布任务继续推进。公开能力与限制以 README 和相关 API 文档为准。

Scripts in `.ci/` currently run manually; they are not configured GitHub Actions workflows. Snapshot/DesiredState/Diff/Plan, protection APIs, dry-run and confirmed Apply CLI are supported. Further integration acceptance and release tasks remain in progress. README and public API documentation define the supported behavior and limitations.

每个小任务完成并验收后独立提交，实现、测试、公开文档和生成接口一同交付。
任务勾选与内部指导仅更新本地 `TODO.md`，不能把该文件加入任务 commit。

Commit each small task independently after completing its acceptance checks, including implementation, tests, public documentation and generated interfaces. Update task checkboxes and internal guidance only in local `TODO.md`; never include that file in a task commit.

提交前检查：

Checks before committing:

```sh
moon check --target native --warn-list +73
moon test --target native
moon fmt --check
moon info --target native
git status --short
git status --ignored --short
git diff --check
git diff --cached --check
git diff --cached --stat
```

Linux 隔离验收：

Isolated Linux acceptance checks:

```sh
bash .ci/validate-queries.sh
bash .ci/validate-link-state.sh
bash .ci/validate-mutations.sh
bash .ci/validate-plan.sh
bash .ci/validate-apply.sh
bash .ci/validate-idempotence.sh
bash .ci/validate-failures.sh
bash .ci/validate-robustness.sh
```

新增源码应明确加入暂存区，再检查暂存清单。不要用 `git add -f` 将被忽略的本地文件
混入提交。推送前读取远程分支状态；已有远程提交应保留，不使用强制推送。

Stage new source files explicitly, then review the staged list. Do not use `git add -f` to include ignored local files. Read the remote branch state before pushing, preserve existing remote commits and do not force-push.
